## 第一章 一句话看懂这项工作

一辆装有 4 颗超广角鱼眼相机的汽车，想知道"周围 360° 都有哪些车、人、障碍物，分别在离我多远的地方"。学术界已经有很好的算法能算出答案，但这些算法里用了几种"挑数据"的操作（grid_sample、gather、scatterND、one-hot），它们在服务器显卡上跑得很好，却在车载低功耗芯片（NPU）上慢得没法用。

**DeployMatBEV 的做法**：不再让芯片在运行时"临时查表挑数据"，而是让神经网络在训练阶段把"图像上的每个位置对应俯视图的哪个格子"这件事**背成几组固定的数字矩阵**。推理时只需要做矩阵乘法——这是车载芯片最擅长、跑得最快的操作。

最终效果：检测精度与原来的几何算法几乎一样（综合分数仅差 0.0052），模型总参数量还减少了 25.8%，并且**推理时完全不再需要相机标定参数**。

## 第二章 背景知识（超级详细版）

这一章占全文最大篇幅，因为它决定了你能否真正理解后面的设计取舍。即使你觉得某些小节"太基础"，也建议快速扫一遍——很多工作多年的工程师对"标定"和"坐标系"的理解也是模糊的。

### 2.1 自动驾驶汽车的"眼睛"与"大脑"

一辆具备辅助驾驶或自动驾驶能力的汽车，身上通常装着这些传感器：

- **摄像头（camera）**：拍彩色图像，便宜、信息量丰富，能看清红绿灯颜色、车道线、障碍物外观，但测不准距离；
- **激光雷达（LiDAR，Light Detection and Ranging，激光探测与测距）**：发射激光束测量周围点的精确距离，得到"点云"，测距准但价格贵、看不清颜色；
- **毫米波雷达（radar）**：用无线电波测距测速，便宜且不受雨雪影响，但分辨率低；
- **超声波雷达**：探测距离很短（几米），主要用于泊车。

这些"眼睛"把数据交给"大脑"——车载计算芯片。大脑要做的第一件事叫**感知（perception）**：弄清楚"周围有什么物体、在哪里、往哪走、速度多快"。感知之后是**预测（prediction）**和**规划控制（planning & control）**。

本文研究的是感知中的一个具体任务：**只用摄像头（而且是鱼眼摄像头），检测车身周围物体的三维位置和尺寸**。

为什么只用摄像头？因为便宜。一颗摄像头几十元人民币，一颗激光雷达曾经要价数万元。量产车要控制成本，"纯视觉方案"是行业的重要方向。

### 2.2 相机是怎么成像的：针孔模型

中学物理告诉我们：把一张纸扎一个小孔，点一支蜡烛放在孔前，纸后的屏幕上会出现**倒立的烛焰**——这就是"小孔成像"，也是所有相机的最简模型，称为**针孔相机模型（pinhole camera model）**。

三维世界中的一个点 P = (X, Y, Z)，经过小孔投影到成像平面上，变成二维点 p = (u, v)。数学上这个投影可以写成：

```
u = fx · (X / Z) + cx
v = fy · (Y / Z) + cy
```

其中：

- `fx`、`fy` 是**焦距**在水平和垂直方向的像素表示，决定"放大倍数"；
- `cx`、`cy` 是**主点**（光轴与成像平面的交点）的像素坐标，通常在图像中心附近。

这四个数合起来构成相机的**内参（intrinsic parameters）**——它们只和相机本身的镜头、传感器有关，和相机装在哪里无关。

**注意一个关键事实**：从三维投到二维，**深度（Z，也就是距离）信息丢失了**。照片里一只近处的小猫和远处的一辆卡车可能看起来一样大——这就是"单张图像测距难"的根本原因，也是后面 Lift-Splat-Shoot 要"猜深度"的原因。

### 2.3 鱼眼相机：看得宽，但世界是弯的

普通相机镜头的视场角（Field of View，FOV）一般只有 30°~90°。想用车载摄像头覆盖车身周围 360°，要么装 6~8 颗普通相机，要么装 4 颗**鱼眼相机（fisheye camera）**——它的镜头是超广角，视场角可达 180°~220°，一颗就能看半个世界。

自动泊车是鱼眼相机的典型战场：泊车时车辆需要看清紧贴车身的障碍物、路沿、儿童、宠物，这些目标都在普通前视相机的视野之外，而四颗鱼眼相机刚好覆盖全车近场区域。

代价是**畸变（distortion）**：鱼眼图像里，直线会变弯，越靠近画面边缘弯曲越严重，物体被拉伸变形。针孔模型完全失效，必须用专门的鱼眼模型（例如 Kannala-Brandt 模型）来描述成像过程：

```
r(θ) = k1·θ + k2·θ³ + k3·θ⁵ + k4·θ⁷ + ...
```

这里的 θ 是入射光线与光轴的夹角，k1~k4 是畸变系数。**对算法的意义是：为普通相机设计的投影公式不能直接套用，处理鱼眼必须额外小心。**

### 2.4 坐标系大家族：像素、图像、相机、自车、世界

新手最容易绕晕的地方来了。一辆车的感知系统里至少存在 5 套坐标系，缺一不可：

1. **像素坐标系（pixel coordinate system）**：以图像左上角为原点，向右为 u 轴，向下为 v 轴，单位是"像素"。神经网络处理图片时用的就是它。
2. **图像坐标系（image coordinate system）**：以主点为原点，单位是物理长度（毫米）。它和像素坐标系之间只差一点缩放和平移（由内参决定）。
3. **相机坐标系（camera coordinate system）**：以镜头光心为原点的三维坐标系，通常 Z 轴朝前（光轴方向），X 轴向右，Y 轴向下。相机"眼中"的世界。
4. **自车坐标系（ego vehicle coordinate system）**：以车身某点（常见是后轴中心在地面的投影）为原点的三维坐标系，X 朝车头方向，Y 朝左，Z 朝上。下游的规划控制模块只认这套坐标系——"前方 10 米有辆车"说的就是它。
5. **世界坐标系（world coordinate system）**：固定在地球某个参考点的全局坐标系，用来把不同时间、不同车辆的数据统一起来。激光雷达坐标系、车身坐标系等中间坐标系也常在数据链路中出现。

**BEV 检测的本质，就是把"像素坐标系里的图像特征"转换到"自车坐标系的俯视平面上"。** 这条转换链要跨越好几套坐标系，每一步都靠下一节讲的坐标变换完成。

### 2.5 坐标变换入门：平移、旋转与齐次坐标

假设你在车头装了一颗相机，想知道"相机看到的点"对应"车身的哪个位置"。这之间隔着一个**刚体变换（rigid body transformation）**：

```
P_ego = R · P_cam + t
```

- **R 是 3×3 的旋转矩阵（rotation matrix）**：描述相机相对车身转了多少角度（比如镜头朝下倾斜了 10°）；
- **t 是 3×1 的平移向量（translation vector）**：描述相机安装在车身的什么位置（比如"后视镜下方，比后轴中心高 1.2 米、靠前 1.5 米"）。

旋转加平移，合称**外参（extrinsic parameters）**——它描述相机相对外界的安装位姿，和内参（相机自身的镜头参数）相对。

为了把"先旋转再平移"写成一次矩阵乘法，工程上使用**齐次坐标（homogeneous coordinates）**：给三维点补一个 1，变成四维 (X, Y, Z, 1)，变换就合并成一个 4×4 矩阵：

```
[ X_ego ]   [ R  t ]   [ X_cam ]
[ Y_ego ] = [      ] · [ Y_cam ]
[ Z_ego ]   [ 0  1 ]   [ Z_cam ]
[  1    ]              [  1    ]
```

于是从像素到自车俯视图的完整链路是：

```
像素 (u,v)
  --内参⁻¹--> 相机坐标系（需要知道深度 Z）
  --外参--> 自车坐标系
  --去掉高度、画到网格--> BEV 平面图
```

在论文和代码里，你经常会看到 `lidar2camera`、`ego2camera`、`lidar2ego`、`ego2img` 这类张量名，它们就是这条链上相邻坐标系之间的 4×4 变换矩阵。**记住这些名字，后面"推理时不需要外参"的意义就明白了。**

### 2.6 相机标定：内参、外参、畸变参数

上面说的内参、外参、畸变系数，工厂生产出来的每颗相机都不一样，必须逐颗实测——这个实测过程就叫**相机标定（camera calibration）**。

**内参标定**的经典做法是"棋盘格法"：

1. 打印一张黑白棋盘格（每个格子尺寸已知，比如 30 毫米）；
2. 举着棋盘格在相机前变换各种角度、距离，拍十几张照片；
3. 算法自动检测每张照片中棋盘格角点的像素位置；
4. 因为角点的真实三维位置已知（棋盘是平的、格子尺寸已知），就可以列出一大堆"三维点 ↔ 二维像素"的对应方程，解出焦距、主点、畸变系数。

鱼眼相机视场角太大、畸变太严重，普通棋盘格工具处理不了，工程上常用 OCamCalib 等专门工具箱（本项目的参考资料里就列了 `ocamcalib_undistort`）。

**外参标定**测的是相机相对车身（或相对其他传感器）的安装位姿。常见方法：把车开到布满标定板的标定间里，多块标定板在自车坐标系中的位置已知，相机看到标定板后就能反解出自己相对车身的位置和姿态。

**关键认知**：传统 BEV 算法在**每次推理时**都要用这些标定参数做实时几何计算；而且换一辆车、相机被碰歪了一点，标定参数就要重测、代码里的变换矩阵就要更新。这就是 DeployMatBEV 想要摆脱的依赖。

### 2.7 数据采集：真实车队与 CARLA 仿真

训练一个三维检测模型需要海量"图像 + 标准答案"数据对。获取方式有两条路：

**真实采集**：改装一辆采集车，装满相机、激光雷达、定位设备，在各种天气、时段、路况下跑路录制。优点是真实，缺点是贵到离谱——一辆车、一套设备、一支车队，再加上后面要讲的标注成本，一个大型数据集动辄数千万人民币。

**仿真采集**：用游戏引擎搭建虚拟城市，在虚拟世界里放一辆装满虚拟相机的车，引擎负责渲染出逼真图像。本文使用的 Fisheye3DOD 数据集就基于 **CARLA 仿真器**（一个专为自动驾驶研究打造的开源仿真平台，基于虚幻引擎）。

仿真的巨大优势：**标准答案免费**。虚拟世界里每辆车的精确三维位置本来就是程序设定的，直接导出即可，一分钱标注费都不用花。代价是**仿真与真实之间存在差距（simulation-to-real gap，仿真到现实差距）**：渲染的光照、材质、畸变特性和真实世界不完全一样，模型在仿真里学得好，到了真实道路上可能打折扣——这个差距在本文第十章还会回来，它和本方法的核心局限直接相关。

### 2.8 数据标注：三维框是怎么"画"出来的

**数据标注（data annotation）**就是给训练数据配上"标准答案"（ground truth，真值）。对二维检测，标注员在图片上拉矩形框、选类别即可；对**三维检测**，要标的是一个三维立方体框：

```
[x, y, z, w, l, h, yaw]
中心点坐标  宽 长 高  朝向角（车头的朝向）
```

在三维点云里手动画三维框极其耗时（一个熟练标注员标一帧也要几分钟）。仿真数据则没有这个问题——真值直接来自引擎。

标注完成后，数据集通常会被整理成标准格式（例如 nuScenes 格式），包含每帧的：图像路径、标定参数、时间戳、三维框列表、类别（轿车、卡车、巴士、行人、骑行者等）。本项目还额外做了一步工程优化：把图像和标注打包成 **LMDB（Lightning Memory-Mapped Database，闪电内存映射数据库）** 格式，让训练容器可以高速顺序读取，避免几万张小图片随机读写拖慢硬盘。

### 2.9 鸟瞰图感知：给汽车一双"上帝之眼"

现在进入感知算法的核心。假设你坐在车里看前视摄像头拍的照片：近处的车大、远处的车小，相邻车道的车互相遮挡——直接在透视图上判断"左后方 5 米有没有车"非常困难。

而规划控制模块需要的输入是一张**俯视平面图**：以自车为中心，标注出周围每个目标的位置、尺寸、朝向。这就像你玩即时战略游戏时的战场小地图——从上往下看，一目了然。

这张俯视平面图就叫**鸟瞰图（Bird's-Eye-View，BEV）**。BEV 感知 pipeline（流水线）的标准结构：

```
多路相机图像
   ↓ 图像编码器（提取特征）
图像特征（仍是透视视角）
   ↓ 视图变换（View Transformation）★ 本文主角
BEV 特征（俯视视角）
   ↓ BEV 编码器（进一步提炼）
   ↓ 检测头（输出每个目标的三维框与类别）
三维检测结果
```

整条链路里，**视图变换是连接"眼睛看到的"和"大脑需要的"之间的桥梁**，也是计算开销最大、部署最麻烦的一步。

### 2.10 Lift-Splat-Shoot：最经典的视图变换三步曲

2020 年提出的 Lift-Splat-Shoot（LSS）是相机 BEV 感知的奠基性工作，后续 BEVDet、Fisheye3DOD 等都沿用了它的框架。它把视图变换拆成三步：

**第一步，Lift（抬升）**：前面说过，单张图片丢失了深度。LSS 的对策是"猜"——让神经网络为每个像素输出一个**深度概率分布**，比如"这个像素有 10% 的概率在 5 米处、30% 的概率在 10 米处、60% 的概率在 15 米处"。把像素按每个可能的深度复制多份并加权，二维像素就被"抬升"成三维空间里一串带权重的点（称为视锥点云，frustum point cloud）。

**第二步，Splat（泼洒）**：用相机内参和外参，把每个三维点变换到自车坐标系，找到它落在 BEV 网格的哪个格子里，把它的特征"泼"进去累加。这一步也叫 **BEV Pooling（BEV 池化）**。

**第三步，Shoot（射击）**：在 BEV 平面上做检测与规划。

这套流程在数学上很优美，但请注意第二步的实现细节：每个三维点落到哪个格子，是**运行时用标定参数算出来的**，不同输入、不同标定，落点完全不同。把特征写进这些格子的操作，硬件上就是 `scatter`（按索引分散写入）；反向从图像上取特征，就是 `gather`（按索引取值）和 `grid_sample`（网格采样）。这正是部署噩梦的开端——下一节先讲硬件，再回头剖析这几个算子。

### 2.11 GPU 与 NPU：两种完全不同的"算盘"

**GPU（Graphics Processing Unit，图形处理器）**：最初为渲染游戏画面设计，后来被发现特别适合训练神经网络。它的特点是拥有**数千个通用计算线程**和**大容量缓存**，像一个有几千名员工的工厂——即使任务杂乱无章（每个员工去不同的仓库货架取货），靠人多也能扛住。训练模型都在 GPU 上做。

**NPU（Neural-network Processing Unit，神经网络处理器）**：专门为神经网络**推理**（用训练好的模型做预测）设计的嵌入式芯片，比如本文的目标平台——地平线征程 6（Horizon Journey 6，简称 J6）。它的设计哲学完全不同：

- 计算靠**乘加阵列（MAC array，Multiply-Accumulate array，乘积累加阵列）**：一大批只能做"乘法和加法"的单元排成规整的阵列，像一台高速运转的流水线算盘；
- 供数据靠 **DMA（Direct Memory Access，直接内存访问）引擎**：它像传送带，按**事先规划好的固定块**，把数据从片外内存搬进片上的小容量高速存储器（SRAM，静态随机存取存储器）；
- 编译器在**编译期**就算好每一步的数据搬运计划（这叫 tiling，切块；以及 double buffering，双缓冲），让传送带永不停歇、算盘永不空转。

这套设计的能效比极高（同样功耗下算力远超 GPU），所以量产车都爱用它。但它有一个命门：

> **所有数据地址必须在编译期可预测。** 一旦某个操作要"等运行时算出索引，才知道去哪里取数据"，传送带就不知道该提前搬什么，算盘只能空转干等——实际算力利用率可能跌到标称值的 10% 以下。

### 2.12 四个"坏"算子逐个剖析：grid_sample、gather、scatterND、one-hot

现在把上一节的硬件认知落到具体算子上。论文点名的四类问题算子，内存访问模式全部是**不规则、数据依赖**的：

**① grid_sample（网格采样）**

做什么：给输出图上每个像素，根据一个**浮点坐标**去输入图上取值。因为坐标落在像素之间，要取周围 4 个像素做**双线性插值**（按距离加权平均）。

生活类比：让你照着一张"寻宝图"去图书馆取书，每本书的位置坐标都带小数（"第 3.7 排、第 8.2 格"），你得在每两个书架之间来回跑，而且**下一个坐标要取完当前这本才告诉你**。

在 BEV 里的角色：BEV 网格上每个格子 → 算出对应的图像浮点坐标 → 采样图像特征。每个格子的采样地址都由运行时几何计算决定，DMA 无法预取。

**② gather（按索引取值）**

做什么：根据一个索引张量，从另一个张量里把对应位置的值挑出来。例如 `gather([10, 20, 30], 索引=[2, 0, 0, 1])` 得到 `[30, 10, 10, 20]`。

生活类比：你去衣柜拿衣服，但拿哪件要看手里一张纸条，纸条内容是出门前刚写的——家人无法提前帮你把衣服摆好。

在 BEV 里的角色：二维 gather 常被用来"替代"grid_sample（先算好离散索引再取值），但索引依然依赖运行时数据，本质上没有解决问题——论文明确指出，作者在 J6 移植实践中验证过这一点。

**③ scatterND（按索引分散写入）**

做什么：gather 的逆操作——把一批值按照索引**写**到目标张量的指定位置。

生活类比：让快递员把一堆包裹按门牌号投进小区信箱，门牌号列表是装车时才生成的，快递员只能在小区里来回折返。

在 BEV 里的角色：LSS 的"泼洒"步骤——每个三维点算出自己的 BEV 格子坐标，然后把特征写进去（scatter 累加）。写地址完全由数据决定，是 NPU 最怕的随机写。

**④ one-hot 构造与相等性掩码**

做什么：one-hot（独热编码）把"类别编号"变成"只有一个位置是 1、其余全是 0"的向量。比如深度分桶编号 7 → `[0,0,0,0,0,0,0,1,0,...]`。实现时通常伴随"比较每个元素是否等于某值"的**数据依赖相等性判断**（equality mask），生成布尔掩码再做筛选。

生活类比：点名时全班都站起来，只有被点到的人保持站立、其他人坐下——看似简单，但要**逐个问过去**才知道谁该站着。

在 BEV 里的角色：LSS 把连续深度离散化成若干深度桶（depth bin），one-hot 用来标记每个像素属于哪个桶，再用掩码做特征筛选累加。

**一句话总结四类算子的共性**：

> 读/写地址要等运行时数据算出来才知道 → DMA 无法预取 → 乘加阵列空转 → NPU 吞吐雪崩。它们不是"不被支持"，而是**与 NPU 的数据流架构根本性不匹配**。

### 2.13 模型量化基础：INT8、PTQ 与 QAT

神经网络训练时用 32 位浮点数（FP32）存储权重和计算。但车载芯片为了省功耗、提速度，推理时通常用 **8 位整数（INT8）**。把 FP32 模型转成 INT8 的过程叫**量化（quantization）**：

- **PTQ（Post-Training Quantization，训练后量化）**：模型训练完之后，用一小批校准数据统计各层数值范围，直接算出缩放系数转成 INT8。快，但精度可能掉；
- **QAT（Quantization-Aware Training，量化感知训练）**：训练时就在前向过程里模拟量化的舍入误差，让网络提前适应。精度更好，但流程复杂。

**和本文的关系**：INT8 矩阵乘法是所有 NPU 工具链里**优化最成熟**的操作（有逐通道缩放系数、硬件级舍入支持）；而 gather、scatter 这类不规则算子即使能量化，每次标量读写都要单独做反量化/再量化，又慢又掉精度。**把核心路径限制为矩阵乘法和逐元素运算，等于自动继承了整个工具链最成熟的量化能力**——代码里预留的 `QuantStub`（量化桩）就是为此准备的挂钩。

## 第三章 问题：为什么现有 BEV 模型"上不了车"

把第二章的零件组装起来，问题链条就非常清晰了：

1. 主流 BEV 检测器（LSS、BEVDet、Fisheye3DOD）的视图变换依赖几何计算：生成参考点、做三维到二维投影、按算出的坐标采样与泼洒；
2. 这些步骤落到硬件上就是 `grid_sample`、二维 `gather`、`scatterND`、one-hot、相等性掩码——全部是不规则内存访问算子；
3. 这类算子在 GPU 上靠"线程多、缓存大"硬扛，在 NPU 上则让传送带停摆、乘加阵列空转；
4. 作者在将公开的 Fisheye3DOD 移植到NPU嵌入式板子的生产实践中亲身遇到：即使把 `grid_sample` 改写成二维 `gather`，依然违反目标 NPU 的高效算子子集，导致推理速度非常慢，量化的模型不能编译，编译的模型不能运行，等等各种问题。

于是论文提出了那个关键的设计问题：

> **能不能让视图变换完全由网络自己学出来，并且只用内存访问规则、编译期可静态分析的算子——也就是 NPU 真正被造出来加速的那类算子？**

DeployMatBEV（论文中名为 DeployBEV）就是对这个问题给出的肯定回答。

## 第四章 核心思想：既然算几何会卡，那就让网络自己"背"下来

用一个生活类比讲清楚传统方法与本方法的区别：

**传统几何方法**像一位每次送货都要现场查导航的快递员：输入目的地（BEV 格子坐标），实时调用地图服务（相机内外参），算出路线（采样坐标），再开车过去（取特征）。每次都要算，每次都走不同的路——导航服务（运行时几何计算）一慢，全城配送都堵。

**DeployMatBEV** 像一位把片区背得滚瓜烂熟的老快递员：训练阶段反复跑同一片区，把"哪个小区对应哪栋楼"全部记在脑子里（几组固定的投影矩阵权重）。上岗后不看导航，直接按记忆走——路线固定、动作规律，效率拉满。

技术化描述：

- **不再**在推理时生成参考点、不再构建 BEV 采样网格、不再用标定参数做实时投影；
- 把"图像特征空间 → BEV 空间"的对应关系**学习为两组投影矩阵**（沿图像高度方向一组、宽度方向一组）；
- 推理时只剩矩阵乘法、转置、softmax、逐元素乘加——全部是规则内存访问算子；
- 相机外参从"推理必需品"降级为"训练数据的隐含背景"——推理时**完全不需要**。

与之前的矩阵化方法（如 MatrixVT）的关键区别：它们的矩阵是**由相机内外参推导出来的固定矩阵**（几何推导），本方法的矩阵是**从数据里端到端学出来的**（学习获得），因此不依赖任何标定参数。

## 第五章 方法详解：自学习可分离矩阵投影

### 5.1 数学根源：矩阵等价变换 $`PAH`$（笔者最初的想法）

> 【作者按】这一节是整个项目真正的出发点，是**我自己的最初想法**。整篇论文、整个项目都是围绕它展开的：图像特征图每个通道就是一个矩阵，目标 BEV 特征图每个通道也是一个矩阵——"矩阵变矩阵"这件事，线性代数里早就研究透了，最核心的工具就是左右各乘一个矩阵的 $`PAH`$ 形式。只要把这件事想明白，"用矩阵替代 LSS"就不再是黑科技，而是水到渠成的选择。

#### 5.1.1 出发点：视图变换本质上就是"矩阵变矩阵"

忘掉所有神经网络的黑话，看最本质的数据形状：

- 图像特征图的一个通道，是一个矩阵 $`A \in \mathbb{R}^{50 \times 50}`$；
- 目标 BEV 特征图的一个通道，是一个矩阵 $`Q \in \mathbb{R}^{128 \times 128}`$。

问题变成：**怎样把矩阵 $`A`$ 变成矩阵 $`Q`$？**

线性代数告诉我们，对一个矩阵做变换，最基本的操作就是**左乘**和**右乘**：

$`Q = P \cdot A \cdot H, \qquad P \in \mathbb{R}^{128 \times 50},\; H \in \mathbb{R}^{50 \times 128}`$

- **左乘 $`P`$ 相当于行变换**：设 $`A`$ 的第 $`i`$ 行为行向量 $`\boldsymbol{a}_i^{\top}`$，则 $`PA`$ 的第 $`i`$ 行是 $`\sum_j p_{ij}\boldsymbol{a}_j^{\top}`$——$`A`$ 各行的线性组合，组合系数就是 $`P`$ 的第 $`i`$ 行。$`A`$ 的行方向正是图像的**高度轴（$`H`$ 轴）**；
- **右乘 $`H`$ 相当于列变换**：对偶地，设 $`A`$ 的第 $`j`$ 列为 $`\boldsymbol{a}_j`$，则 $`AH`$ 的第 $`j`$ 列是 $`\sum_i \boldsymbol{a}_i h_{ij}`$——$`A`$ 各列的线性组合。$`A`$ 的列方向正是图像的**宽度轴（$`W`$ 轴）**。

于是一切都对上了：**所谓"沿高度方向投影"就是左乘 $`P`$，所谓"沿宽度方向投影"就是右乘 $`H`$，可分离矩阵投影 $`\equiv`$ $`PAH`$ 矩阵等价变换**。LSS 那套"猜深度 $`\to`$ 算坐标 $`\to`$ 泼洒"的复杂几何流程，从线性代数视角看，只是实现"矩阵变矩阵"的一种迂回方式；既然 $`PAH`$ 就能直接完成这个变换，为什么不能把 $`P`$ 和 $`H`$ 当作参数让网络自己学出来？这就是整个项目的第一粒种子。

#### 5.1.2 情形一：$`P`$、$`H`$ 可逆（初等行、列变换 / 相抵变换）

**预备知识：初等矩阵。** 三类初等行变换各对应一个初等矩阵：

1. 交换第 $`i`$、$`j`$ 两行：$`E(i,j)`$；
2. 第 $`i`$ 行乘以非零常数 $`c`$：$`E\big(i(c)\big)`$；
3. 第 $`j`$ 行的 $`k`$ 倍加到第 $`i`$ 行：$`E\big(i,j(k)\big)`$。

每个初等矩阵都可逆（其逆仍是同类初等矩阵，如 $`E\big(i,j(k)\big)^{-1} = E\big(i,j(-k)\big)`$）。对 $`A`$ 做一次初等行变换 $`\Longleftrightarrow`$ 左乘一个初等矩阵；做一次初等列变换 $`\Longleftrightarrow`$ 右乘一个初等矩阵。

> **定理（等价标准形）**：设 $`A \in \mathbb{R}^{m \times n}`$，$`\mathrm{rank}(A) = r`$，则存在可逆矩阵 $`P \in \mathbb{R}^{m \times m}`$、$`H \in \mathbb{R}^{n \times n}`$，使得
> $`PAH = E_r = \begin{pmatrix} I_r & O \\ O & O \end{pmatrix}`$
> 其中 $`I_r`$ 是 $`r`$ 阶单位阵，其余块全为零矩阵。

**证明（高斯消元的矩阵语言，逐步）**：

- **第一步（行变换消元）**：对 $`A`$ 做高斯消元。若第 1 列存在非零元 $`a_{i1} \neq 0`$，先交换第 1、$`i`$ 行（左乘 $`E(1,i)`$），再用主元把第 1 列其余元素消成 0（依次左乘 $`E\big(i,1(-a_{i1}/a_{11})\big)`$）；若第 1 列全零则直接看第 2 列。对右下角的子块递归重复。有限步后得到行阶梯形：
$`P_s \cdots P_2 P_1 \cdot A = \begin{pmatrix} U_r \\ O \end{pmatrix}, \qquad U_r \text{ 是 } r \text{ 行的满秩阶梯形}`$
- **第二步（列变换清零）**：对 $`\begin{pmatrix} U_r \\ O \end{pmatrix}`$ 右乘初等矩阵做列消元——用每行的主元把该行右侧的元素全部清零，得到 $`\begin{pmatrix} D_r & O \\ O & O \end{pmatrix}`$，其中 $`D_r = \mathrm{diag}(d_1, \dots, d_r)`$，$`d_i \neq 0`$；
- **第三步（主元缩放为 1）**：左乘对角缩放阵 $`\mathrm{diag}(d_1^{-1}, \dots, d_r^{-1}, 1, \dots, 1)`$，把 $`D_r`$ 变成 $`I_r`$；
- **收尾**：把所有左乘的初等矩阵（含缩放阵）按顺序攒成 $`P`$，所有右乘的攒成 $`H`$。初等矩阵均可逆，可逆矩阵之积仍可逆，故 $`P`$、$`H`$ 可逆，且 $`PAH = E_r`$。$`\blacksquare`$

> **推论（相抵的充要条件）**：对两个同型矩阵 $`A`$、$`B`$，"存在可逆 $`P`$、$`H`$ 使 $`B = PAH`$" $`\Longleftrightarrow`$ $`\mathrm{rank}(A) = \mathrm{rank}(B)`$。

**证明（两个方向分别证）**：

($`\Rightarrow`$) 可逆矩阵是满秩的，乘以满秩矩阵不改变秩（可逆变换是线性同构，既不压缩也不扩张像空间），故 $`\mathrm{rank}(B) = \mathrm{rank}(PAH) = \mathrm{rank}(A)`$。

($`\Leftarrow`$) 设 $`\mathrm{rank}(A) = \mathrm{rank}(B) = r`$。由等价标准形定理，存在可逆矩阵 $`P_A, H_A, P_B, H_B`$ 使
$`A = P_A^{-1} E_r H_A^{-1}, \qquad B = P_B^{-1} E_r H_B^{-1}`$
由第一式解出 $`E_r = P_A A H_A`$，代入第二式：
$`B = P_B^{-1} (P_A A H_A) H_B^{-1} = \underbrace{(P_B^{-1} P_A)}_{P}\, A\, \underbrace{(H_A H_B^{-1})}_{H}`$
可逆矩阵的逆与乘积仍可逆，故这正是 $`B = PAH`$ 且 $`P`$、$`H`$ 可逆的形式。$`\blacksquare`$

**这条推论的直白含义**：当 $`P`$、$`H`$ 可逆时，$`PAH`$ 的可达集合是
$`\{Q : \mathrm{rank}(Q) = \mathrm{rank}(A)\}`$
即**所有与 $`A`$ 同型、同秩的矩阵**——是一个很大的集合，但**不是全部矩阵**。秩变了，就到不了；不变量是秩。

#### 5.1.3 情形二：$`P`$、$`H`$ 任意（不一定可逆）

> **引理（矩阵乘积的秩）**：对任意尺寸相容的矩阵 $`X`$、$`Y`$，有 $`\mathrm{rank}(XY) \le \min\big(\mathrm{rank}(X), \mathrm{rank}(Y)\big)`$。

**证明**：$`XY`$ 的第 $`j`$ 列是 $`X(Y\boldsymbol{e}_j)`$，即 $`X`$ 各列的线性组合，故列空间满足 $`\mathrm{Col}(XY) \subseteq \mathrm{Col}(X)`$，维数给出 $`\mathrm{rank}(XY) \le \mathrm{rank}(X)`$；对偶地，行空间 $`\mathrm{Row}(XY) \subseteq \mathrm{Row}(Y)`$ 给出 $`\mathrm{rank}(XY) \le \mathrm{rank}(Y)`$。$`\blacksquare`$

连续用两次引理：

$`\mathrm{rank}(PAH) \le \min\big(\mathrm{rank}(P), \mathrm{rank}(AH)\big) \le \min\big(\mathrm{rank}(P), \mathrm{rank}(A), \mathrm{rank}(H)\big) \le \mathrm{rank}(A)`$

即**无论 $`P`$、$`H`$ 怎么取，$`\mathrm{rank}(Q) \le \mathrm{rank}(A)`$，秩被 $`\mathrm{rank}(A)`$ 封项**。

**反向可达性**：任意满足 $`\mathrm{rank}(Q) = s \le r`$ 的同型矩阵 $`Q`$ 都能被 $`PAH`$ 达到。

**证明（构造法）**：对 $`Q`$ 自身做等价分解 $`Q = P_Q E_s H_Q`$。取对角投影阵
$`D_s = \mathrm{diag}(\underbrace{1, \dots, 1}_{s \text{ 个}}, 0, \dots, 0) \in \mathbb{R}^{m \times m}`$
（$`D_s`$ 不要求可逆），直接验证 $`E_s = D_s E_r D_s'`$（$`D_s'`$ 是 $`n`$ 阶同型对角投影阵）。再代入 $`A`$ 的标准形 $`E_r = P_A A H_A`$：

$`Q = P_Q D_s E_r D_s' H_Q = \underbrace{(P_Q D_s P_A)}_{P}\, A\, \underbrace{(H_A D_s' H_Q)}_{H} \quad \blacksquare`$

**两种情形的可达集合汇总**：

| $`P`$、$`H`$ 的约束 | 可达集合 | 不变量 |
|:------------|:---------|:------:|
| 可逆 | $`\{Q : \mathrm{rank}(Q) = \mathrm{rank}(A)\}`$，所有同型同秩矩阵 | 秩 |
| 任意 | $`\{Q : \mathrm{rank}(Q) \le \mathrm{rank}(A)\}`$ | 秩的上限 |

无论哪种情形，**$`\mathrm{rank}(A)`$ 都是一道天花板**——可逆时锁死，任意时封顶。

#### 5.1.4 几何角度：为什么换基改变不了秩

矩阵 $`A`$ 本身代表一个**线性映射** $`T: V \to W`$（从定义域空间 $`V`$ 映到值域空间 $`W`$）。取 $`V`$ 的一组基、$`W`$ 的一组基，$`A`$ 就是 $`T`$ 在这对基下的矩阵表示。

- **右乘可逆 $`H`$**：输入换坐标，$`x = Hx'`$，则 $`y = AHx'`$——相当于在**定义域空间 $`V`$ 里换一组基**；
- **左乘可逆 $`P`$**：输出换坐标，$`y' = Py`$，则 $`y' = PAHx'`$——相当于在**值域空间 $`W`$ 里换一组基**。

而秩 $`\mathrm{rank}(A) = \dim \mathrm{Im}(T)`$（像空间的维数）是映射 $`T`$ 的**内在属性**，与用什么坐标系描述它毫无关系。所以换基之后，映射的"有效维度"不变，自然无法得到秩更大的映射。

用一个生活例子理解：一幅地图（$`A`$）把"经纬度"映到"屏幕像素"。左乘 $`P`$ 相当于把屏幕坐标从像素换成厘米（换输出的度量衡），右乘 $`H`$ 相当于把经纬度换成投影坐标（换输入的度量衡）——地图能表达的信息量（秩）一点没变，因为地图本身没变。

#### 5.1.5 落到代码：$`PAH`$ 在视图变换器里长什么样

对照 `view_transformerFisheye.py` 的 `_spatial_transfom_learn`，每个通道的图像特征 $`A \in \mathbb{R}^{50 \times 50}`$ 经历的正是：

```python
Ã = A · H            # matmul(img_feat, param)：右乘，作用在宽度 W（列变换）
Q = P · Ã            # permute 后再 matmul：等价于左乘，作用在高度 H（行变换）
```

合起来就是 $`Q = PAH`$。以 v2 为例，宽度链 $`H = H_1 H_2 \in \mathbb{R}^{50 \times 128}`$（$`H_1 \in \mathbb{R}^{50 \times 256}`$、$`H_2 \in \mathbb{R}^{256 \times 128}`$），高度链 $`P = P_2^{\top} P_1^{\top} \in \mathbb{R}^{128 \times 50}`$（permute 转置带来的转置次序）。$`P`$ 相当于行变换，$`H`$ 相当于列变换——与笔者的原始想法一一对应。

**笔者自己的几何解释（逐元素看"特征移动与累加"）**：

- **右乘 $`H`$（宽度轴）**：$`(AH)_{ij} = \sum_k A_{ik} H_{kj}`$，即输出第 $`i`$ 行 $`(AH)_{i,:} = \boldsymbol{a}_{i,:}^{\top} H`$。对 $`A`$ 的**每一行**（一行 = 同一高度上沿宽度方向排列的特征），$`H`$ 把这一行里第 $`k`$ 个宽度位置的特征，以权重 $`H_{kj}`$ **移动并累加**到新的第 $`j`$ 个宽度位置。关键点：每一行被同一个 $`H`$ **独立**处理，行与行之间在这一步不发生任何混合；
- **左乘 $`P`$（高度轴）**：$`(PA)_{ij} = \sum_k P_{ik} A_{kj}`$，即输出第 $`j`$ 列 $`(PA)_{:,j} = P\boldsymbol{a}_{:,j}`$。对 $`A`$ 的**每一列**（一列 = 同一宽度上沿高度方向排列的特征），$`P`$ 把第 $`k`$ 个高度位置的特征**移动并累加**到新的第 $`i`$ 个高度位置。每一列独立处理，列与列之间不混合；
- **合起来**：$`Q_{ij} = \sum_{k,l} P_{ik} A_{kl} H_{lj}`$——输入特征图的**每个像素 $`(k, l)`$ 都以可分离权重 $`P_{ik} H_{lj}`$ 贡献到每个输出像素 $`(i, j)`$**。这正是"可分离"的几何含义：二维的特征搬运被分解为"先沿宽度搬一次，再沿高度搬一次"。

**通道共享：当前实现的一个重要性质。** 投影矩阵的形状是 `[num_views, ...]`，只按视角区分（4 路相机各一套），**不含通道维**。`torch.matmul(img_feat, param)` 中 `img_feat` 为 $`[B, C, 50, 50]`$、`param` 为 $`[50, R]`$，对批次维 $`B`$ 和通道维 $`C`$ 广播——**同一张图片的所有特征通道共用同一套 $`P`$、$`H`$**。也就是说：空间维度的搬运是"通道无关"的，而通道维度的信息混合由投影前的 1×1 卷积（`feat_net` / `depth_net`）负责。这与卷积网络的结构形成漂亮的互补：**1×1 卷积只混合通道、不移动空间位置；投影矩阵只移动空间位置、不混合通道**。

#### 5.1.6 秩分析：纯矩阵形式的天花板在哪里

把 5.1.3 的结论代入本项目的具体数字：

- $`A \in \mathbb{R}^{50 \times 50}`$，$`\mathrm{rank}(A) \le 50`$；
- $`Q \in \mathbb{R}^{128 \times 128}`$，理论满秩 128，但 $`PAH`$ 形式给出 $`\mathrm{rank}(Q) \le 50`$。

也就是说，**单个通道的 BEV 特征矩阵最多是秩 50 的**——这是纯 $`PAH`$ 形式绕不开的固有约束。这也顺带解释了一个消融现象：v2、v3 在纯矩阵链中没有非线性，$`P_2^{\top}P_1^{\top}`$ 乘起来仍是一个 $`128 \times 50`$ 矩阵、$`H_1H_2`$ 仍是 $`50 \times 128`$，**秩上限与 v1 完全相同**——v2/v3 的收益来自更好的优化动力学（更深的链更好训），而非更高的表达上限。

但请注意三个缓解因素，它们解释了为什么最终 NDS 仍然能逼近几何基线：

1. **64 个通道**：秩约束是"每个通道"级别的，64 个通道各自承载不同的低秩结构，合起来的张量表达能力仍然很强；
2. **4 路视角求和**：$`\mathrm{rank}(B_1 + B_2) \le \mathrm{rank}(B_1) + \mathrm{rank}(B_2)`$，四个秩 $`\le 50`$ 的矩阵相加，理论上可以铺满 128 维——多视角聚合在无意中扮演了"秩扩张器"的角色；
3. **BEV 编码器的非线性**：视图变换之后还有带激活函数的卷积骨干，非线性会打破秩约束。

#### 5.1.7 小结

| 问题 | 答案 |
|:-----|:-----|
| 视图变换的本质 | 矩阵 $`A`$（图像特征）$`\to`$ 矩阵 $`Q`$（BEV 特征） |
| 最直接的工具 | $`Q = PAH`$，左乘 $`P`$ = 行变换（高度轴），右乘 $`H`$ = 列变换（宽度轴） |
| $`P`$、$`H`$ 可逆时可达集合 | $`\{Q : \mathrm{rank}(Q) = \mathrm{rank}(A)\}`$（不变量：秩） |
| $`P`$、$`H`$ 任意时可达集合 | $`\{Q : \mathrm{rank}(Q) \le \mathrm{rank}(A)\}`$ |
| 本项目的天花板 | 单通道 $`\mathrm{rank}(Q) \le 50`$（$`A`$ 是 $`50 \times 50`$） |
| 缓解手段 | 64 通道 $`\times`$ 4 视角求和 $`\times`$ 后续非线性 |

### 5.2 问题形式化

4 路鱼眼相机（前、左、后、右）各输出一份特征图：

```
F_i ∈ R^(C×H×W)     图像特征（C=64 通道，H=W=50）
D_i ∈ R^(C×H×W)     深度门控特征（同尺寸，由 1×1 卷积 + 通道 softmax 得到）
```

目标：产出统一的 BEV 特征 `B ∈ R^(C×H_b×W_b)`（H_b = W_b = 128），交给下游检测头。

### 5.3 为什么必须是"可分离"的

最笨的办法：学一个把 50×50=2500 个像素直接映射到 128×128=16384 个格子的超级大矩阵，参数量 2500×16384 ≈ 4100 万，比很多骨干网络还大，完全不可行。

**可分离（separable）设计**把二维变换拆成两个一维变换：

```
先沿宽度方向投影：W(50) → W_b(128)
再沿高度方向投影：H(50) → H_b(128)
```

直觉理解：先回答"图像的每一列对应 BEV 的哪一列"，再回答"图像的每一行对应 BEV 的哪一行"。参数量从 O(H·W·H_b·W_b) 骤降到 O(W·R + R·W_b + H·R + R·H_b)（R 是隐藏维度，取 256），四个相机加起来的投影参数也只有 0.1M~1.78M。

### 5.4 逐步推导（以默认的 version 2 为例）

每路相机 i 学两组矩阵，图像分支与深度分支各一组。图像分支：

```
P^w_{i,1} ∈ R^(50×256),  P^w_{i,2} ∈ R^(256×128)   宽度方向两段
P^h_{i,1} ∈ R^(50×256),  P^h_{i,2} ∈ R^(256×128)   高度方向两段
```

**第一步：宽度投影。** 对特征图每个通道、每一行（长度 50 的向量），连续乘两个矩阵：

```
行向量(50维) × P^w_{i,1} → 256维 × P^w_{i,2} → 128维
```

整个特征图变成 `F̃_i ∈ R^(C×50×128)`。

**第二步：转置后做高度投影。** 把张量的最后两维交换（permute），让高度维暴露在最后，同样连乘两个矩阵：

```
列向量(50维) × P^h_{i,1} → 256维 × P^h_{i,2} → 128维
```

得到图像分支的 BEV 张量 `B_i^F ∈ R^(C×128×128)`。

**第三步：深度门控分支。** 结构完全镜像（独立的 Q 系列矩阵）。区别在于投影前，图像特征先过一个 1×1 卷积，再沿通道维度做 softmax——把每个像素的通道值归一化成"总和为 1 的概率分布"，相当于让网络为每个像素学一个"该往 BEV 里投多少置信度"的软开关（论文称为深度门控/软遮挡开关）。投影后得到 `B_i^D`。

**第四步：融合与聚合。**

```
B_i = B_i^F ⊙ B_i^D      逐元素相乘：门控筛选
B   = B_1 + B_2 + B_3 + B_4    四路相机求和
```

### 5.5 三个容量版本：一个旋钮控制"记忆力深浅"

配置文件的 `learning_point_version` 超参数控制矩阵链的深度：

| 版本 | 每个轴的投影路径 | 矩阵乘法层数/分支 | 投影参数量（4 路合计） |
|:----:|:----------------:|:-----------------:|:----------------------:|
| v1 | 50 → 128 | 2 | 0.10M |
| v2 | 50 → 256 → 128 | 4 | 0.73M |
| v3 | 50 → 256 → 256 → 128 | 6 | 1.78M |

三个版本的**算子种类一字不差**，只有链条深浅之别——给部署侧一个干净的"容量 ↔ 成本"调节旋钮。

### 5.6 下一步计划（TODO）：如何突破 $`\mathrm{rank}(A)`$ 的天花板

5.1 节的分析指出，纯 $`PAH`$ 形式的可达集合被 $`\mathrm{rank}(A)`$ 封顶。想要**"把 $`A`$ 变成任意矩阵"**，目前规划了两个方案，下面把动机、数学原理、代价估算、代码改动点和验证实验逐一写清楚。

#### 方案一：放弃纯乘法形式，改用仿射变换 $`Q = P \cdot A \cdot H + B`$

**动机**：纯 $`PAH`$ 是**线性映射**——零输入必得零输出（$`A = O \Rightarrow Q = O`$），且秩被 $`\mathrm{rank}(A)`$ 封顶。

**做法**：引入可学习偏移矩阵 $`B \in \mathbb{R}^{128 \times 128}`$：

$`Q = P \cdot A \cdot H + B`$

这等价于把"线性变换"升级为"仿射变换"，与神经网络里 $`y = Wx`$ 升级为 $`y = Wx + b`$ 完全同构。

**为什么有效**：

- **秩约束解除**：$`B`$ 本身可以是满秩 128 的矩阵，$`\mathrm{rank}(PAH + B)`$ 不再受 $`\mathrm{rank}(A)`$ 约束。极端例子：取 $`P = O`$、$`H = O`$、$`B = I_{128}`$，则 $`Q = I_{128}`$ 满秩——纯 $`PAH`$ 永远做不到这一点；
- **几何意义**：$`PAH`$ 只能做"过原点的线性映射"，特征空间的原点被固定；$`+B`$ 之后允许整体平移，特征的"零点"也可以自由移动，映射族从线性映射扩大为仿射映射。

**代价估算**：每个视角、每个分支增加 $`128 \times 128 = 16384`$ 个参数；4 视角 $`\times`$ 2 分支共约 $`0.13`$M，相对整网 14.5M 可忽略。加法本身是规则内存访问算子，**部署友好性不受任何影响**。注意多视角求和后等效于 $`Q_{\text{总}} = \sum_i P_iA_iH_i + \sum_i B_i`$，偏移同样逐视角独立。

**代码改动点**（`_spatial_transfom_learn` 内）：

```python
# __init__ 中新增
self.bias_bev = nn.Parameter(torch.zeros(num_views, 1, grid_size[0], grid_size[1]))
# 前向中，每个视角的融合前/后加偏移
flat_bev = flat_bev + self.bias_bev[i]          # Q = PAH + B
```

**验证实验**：v1 / v2 / v3 三个版本分别加偏移训练，对比 NDS / mAP 变化；可视化学习到的 $`B`$ 是否呈现类似"先验占据图"的结构（道路区域亮、天空区域暗）。

#### 方案二：改用向量视角，用线性组合替代左右乘 $`Q = \sum_{k=1}^{K} P_k A H_k`$

**动机**：不再执着于"左右各乘一个矩阵"，把矩阵 $`A`$ 看成矩阵空间里的一个**向量**，用一组基矩阵的线性组合来构造 $`Q`$。

**数学依据（克罗内克积推导，逐步）**：记 $`\mathrm{vec}(\cdot)`$ 为按列拉直算子（把 $`m \times n`$ 矩阵拉成 $`mn`$ 维列向量）。利用经典恒等式（可对 $`X`$ 的第 $`j`$ 列 $`X\boldsymbol{e}_j`$ 逐列验证）：

$`\mathrm{vec}(AXB) = (B^{\top} \otimes A)\,\mathrm{vec}(X)`$

代入左乘 $`P`$、右乘 $`H`$：

$`\mathrm{vec}(PAH) = (H^{\top} \otimes P)\,\mathrm{vec}(A)`$

代入本项目数字：$`\mathrm{vec}(A) \in \mathbb{R}^{2500}`$，$`\mathrm{vec}(Q) \in \mathbb{R}^{16384}`$。**一般的**线性映射需要矩阵 $`W \in \mathbb{R}^{16384 \times 2500}`$（约 4100 万参数，不可行）；$`PAH`$ 只用 $`P`$（$`128 \times 50 = 6400`$）$`+`$ $`H`$（$`50 \times 128 = 6400`$）$`= 12800`$ 个参数，但只能表示形如 $`H^{\top} \otimes P`$ 的"克罗内克结构化"映射——它只占全部线性映射的极小一部分。而 $`K`$ 项求和：

$`\mathrm{vec}(Q) = \sum_{k=1}^{K} (H_k^{\top} \otimes P_k)\,\mathrm{vec}(A)`$

对应"克罗内克秩 $`\le K`$"的映射族；$`K`$ 增大时该族在全体线性映射中越来越稠密，$`K`$ 足够大时可精确表示任意线性映射。

**为什么有效（秩视角）**：每一项 $`P_k A H_k`$ 的秩仍不超过 $`\mathrm{rank}(A)`$，但**求和可以提升秩**：

$`\mathrm{rank}(Q) = \mathrm{rank}\Big(\sum_{k=1}^{K} P_k A H_k\Big) \le \sum_{k=1}^{K} \mathrm{rank}(P_k A H_k) \le K \cdot \mathrm{rank}(A) = 50K`$

$`K = 3`$ 时上限已达 $`150 \ge 128`$，允许满秩。

**与现有设计的联系**：当前的"4 路视角求和"已是跨视角的 $`K = 4`$ 混合投影（各视角输入 $`A_i`$ 不同），"图像/深度双分支"相当于 $`K = 2`$。方案二只是把这个思想从"跨视角"细化到"单视角内部"：每路相机学 $`K`$ 套矩阵 $`(P_k, H_k)`$，求和后输出。

**代价估算**：直接投影情形下每套 $`(P_k, H_k)`$ 为 12800 参数，参数量与计算量随 $`K`$ 线性增长；实现上把 $`K`$ 作为额外批次维，用批量矩阵乘法（`bmm` / `einsum`）一次算完再求和，仍是纯规则算子。

**验证实验**：$`K = 1, 2, 3, 4`$ 消融，观察 NDS / mAP 是否随 $`K`$ 提升并在何处饱和；进一步与方案一组合：$`Q = \sum_k P_k A H_k + B`$。

#### 补充：几何角度的统一理解

矩阵 $`A`$ 代表一个线性映射；左乘可逆 $`P`$ 改变值域空间的基，右乘可逆 $`H`$ 改变定义域空间的基；换基不改变映射的秩（像空间维数固定），所以纯 $`PAH`$ 永远得不到秩更大的映射。方案一的 $`+B`$ 引入了映射的**平移自由度**（线性 $`\to`$ 仿射），方案二的求和引入了**多个映射的叠加自由度**——两者分别从不同方向突破秩约束，后续将做消融实验验证。


两个细节值得新手注意：

- **第一维是 4**——每路相机拥有自己的一套矩阵，对应论文的"视角特定（view-specific）"设计。前后左右四颗相机的安装朝向不同，各自学习自己的映射关系；
- **初始化除以 `row_sum`**（= 特征尺寸 × 视角数）做缩放，防止随机初始化的矩阵连乘后数值爆炸，让训练起步更平稳。

### 6.2 双分支特征提取：`_extract`（第 1587 行）

```python
depth = self.softmax(self.depth_net(feats))   # 1×1 卷积 → 通道维 softmax：深度门控
new_feats = self.feat_net(feats)              # 1×1 卷积：图像特征
return new_feats, depth
```

`depth_net` 和 `feat_net` 都是 1×1 卷积（第 832、843 行，1×1 卷积等价于对每个像素的通道做一次全连接变换）；`softmax` 沿通道维（dim=1，第 851 行），把每个像素归一化成概率分布。这一步是全文唯一的"非线性门控"，但它本身也是规则算子。

### 6.3 核心变换：`_spatial_transfom_learn`（第 1606 行起）

v3 分支（第 1631 行）对每路相机循环：

```python
for i in range(self.num_views):                    # 4 路相机
    img_feat   = feat[i]                           # [B, C, 50, 50]
    depth_feat = dfeat[i]

    # ── 图像分支：宽度方向 50→256→256→128 ──
    flat_bev = torch.matmul(img_feat,  self.param_point2[i])
    flat_bev = torch.matmul(flat_bev,  self.param_point22[i])
    flat_bev = torch.matmul(flat_bev,  self.param_point222[i])
    flat_bev = flat_bev.permute((0, 1, 3, 2))      # 交换最后两维，暴露 H

    # ── 图像分支：高度方向 50→256→256→128 ──
    flat_bev = torch.matmul(flat_bev,  self.param_point1[i])
    flat_bev = torch.matmul(flat_bev,  self.param_point11[i])
    flat_bev = torch.matmul(flat_bev,  self.param_point111[i])
    flat_bev = flat_bev.permute((0, 1, 3, 2))

    # ── 深度分支：完全镜像（dparam_point* 系列）──
    flat_depth_bev = torch.matmul(depth_feat, self.dparam_point2[i])
    ...                                            # 同样 6 次 matmul + 2 次 permute

    # ── 量化桩 + 门控融合 ──
    bev_img_fp   = self.bev_quant(flat_bev)        # QAT 挂钩，浮点阶段是恒等映射
    bev_depth_fp = self.depth_bev_quant(flat_depth_bev)
    fused = bev_img_fp * bev_depth_fp              # ⊙ 逐元素乘
    flat_bev_col.append(fused)
```

循环结束后（第 2010 行），四路结果逐元素相加：

```python
trans_feat = flat_bev_col[0]
for f in flat_bev_col[1:]:
    trans_feat = self.floatFs.add(trans_feat, f)   # B = Σ B_i
```

**整个函数只有 `matmul`、`permute`、`QuantStub`、乘法、加法**——一个不规则内存访问算子都没有。这就是论文标题中"Self-Learned Matrix View Transformer（自学习矩阵视图变换器）"的全部含义。

### 6.4 nuScenes 扩展版（v9 / v10 / v11，第 1742~2009 行）

为 6 路针孔相机的 nuScenes 数据集准备的扩展变体，在矩阵链之间插入批归一化（BatchNorm）与残差连接。动机很深刻：**纯矩阵乘法链条在数学上可以折叠成一个矩阵**（线性变换复合仍是线性变换），v1~v3 的多层收益主要来自优化动力学；插入归一化/非线性后，深度才带来真实容量。这是论文附录与 README 附录都明确的后续改进点，第十章详述。

## 第七章 网络整体架构与训练配置

完整数据流（从传感器到三维框）：

```
4× 鱼眼图像 (800×800)
   ↓ EfficientNet-B0 图像编码器（ImageNet 预训练，去掉分类头）
   ↓ FastSCNN 风格特征颈部（融合 16 倍与 32 倍下采样特征 → 64 通道）
图像特征 (64×50×50) × 4 路
   ↓ 双分支：feat_net（1×1卷积） / depth_net（1×1卷积+通道softmax）
   ↓ 自学习可分离矩阵投影（每路相机独立矩阵，50×50 → 128×128）
   ↓ 逐元素门控融合 ⊙
   ↓ 4 路求和
统一 BEV 特征 (64×128×128)
   ↓ BEV 编码器（EfficientNet 风格 + BiFPN 颈部，48 通道）
   ↓ 中心点检测头（CenterPoint 风格：热图 + 回归）
三维框 [x, y, z, w, l, h, yaw]
```

关键超参数（来自 `config/bev_lss_efficientnetb0_multitask_nuscenes.py` 与论文）：

| 参数 | 数值 |
|:-----|:----:|
| 输入分辨率 | 800 × 800 |
| 骨干下采样后特征图 | 50 × 50（16 倍下采样） |
| BEV 网格 | 128 × 128 |
| BEV 物理范围 | 51.2 米 × 51.2 米（每格 0.4 米） |
| 图像/深度特征通道 | 64 / 64 |
| 隐藏投影维度 R | 256 |
| 优化器 | AdamW（初始学习率 2×10⁻⁴，权重衰减 0.01） |
| 学习率调度 | 循环学习率 |
| 训练轮数 | 36（浮点阶段） |
| 显卡数 / 单卡批量 | 4 / 1（等效批量 4） |

损失函数：中心热图用高斯焦点损失（Gaussian Focal Loss），框回归项用 L1 损失。训练评测均在地平线 OpenExplorer 容器（Docker 镜像 `docker_open_explorer_ubuntu_22_j6_gpu_v3.8.1`）中完成，与后续 J6 板端部署共用同一条工具链。

## 第八章 实验结果：精度几乎不掉，参数反而更少

### 8.1 评测指标扫盲

采用 nuScenes 检测体系的四个指标：

- **mAP（mean Average Precision，平均精度均值）**：检测框有多准，越高越好；
- **mATE（mean Average Translation Error，平均平移误差）**：预测框中心偏了多少米，越低越好；
- **mASE（mean Average Scale Error，平均尺度误差）**：框的尺寸错了多少，越低越好；
- **mAOE（mean Average Orientation Error，平均朝向误差）**：车头朝向角错了多少弧度，越低越好；
- **NDS（nuScenes Detection Score，nuScenes 检测分数）**：以上指标加权合成的综合分，越高越好。

### 8.2 主结果（Fisheye3DOD 验证集）

| 方法 | 只用规则内存算子 | mAP↑ | mATE↓ | mASE↓ | mAOE↓ | NDS↑ |
|:-----|:----------------:|:----:|:-----:|:-----:|:-----:|:----:|
| 原始 Fisheye3DOD（几何基线） | 否 | **0.3821** | **0.5906** | 0.1637 | 0.4799 | **0.4853** |
| DeployMatBEV v1 | 是 | 0.3047 | 0.7160 | 0.1324 | 0.4489 | 0.4361 |
| DeployMatBEV v2 | 是 | 0.3132 | 0.7202 | 0.1399 | 0.4448 | 0.4392 |
| DeployMatBEV v3 | 是 | 0.3533 | 0.6478 | **0.1319** | 0.4209 | 0.4766 |
| DeployMatBEV v3*（延长训练） | 是 | 0.3515 | 0.6578 | 0.1333 | **0.3826** | **0.4801** |

三个要点：

1. **NDS 差距仅 0.0052**——视图变换全部换成 NPU 原生矩阵算子后，综合检测质量与几何基线几乎持平；
2. **尺度与朝向误差反而更好**：mAOE 从 0.4799 降到 0.3826，mASE 从 0.1637 降到 0.1319；
3. mAP 差距更大（0.3515 vs 0.3821），说明纯学习式映射对小目标/远处目标召回略逊——论文坦诚承认了这一点。

### 8.3 参数量对比

| 模型 | 视图变换可学习参数 | 总参数量 | 检查点大小 |
|:-----|:------------------:|:--------:|:----------:|
| 原始 Fisheye3DOD | 0.05M（另有 1.44M 不可学习几何缓冲区） | 19.48M | 235.4 MB |
| DeployMatBEV v1 | 0.10M | 12.79M | 82.1 MB |
| DeployMatBEV v2 | 0.73M | 13.41M | 89.6 MB |
| DeployMatBEV v3 | 1.78M | 14.46M | 102.2 MB |

最大的 v3 总参数量也比基线**少 25.8%**。基线更臃肿的原因：ResNet-18 + FPN 图像骨干、SECOND BEV 骨干，外加 1.44M 个由标定参数生成的几何缓冲区（视锥网格与球面网格）——这些缓冲区在相机安装方案变更时必须重新生成，而学习式矩阵只需重新训练。

### 8.4 容量消融

v1（0.4361）→ v2（0.4392）→ v3（0.4766~0.4801）的 NDS 爬升证明：视图变换的表达能力确实受益于更深的投影链，且**新增容量全部来自更多矩阵乘法，没有引入任何不规则算子**。

### 8.5 分类别结果（v3* 最佳检查点）

| 类别 | AP↑ | ATE↓ | ASE↓ | AOE↓ |
|:-----|:---:|:----:|:----:|:----:|
| 轿车 | 0.3277 | 0.6691 | 0.2052 | 0.1491 |
| 厢式车 | 0.3547 | 0.5881 | 0.1938 | 0.1397 |
| 卡车 | 0.3876 | 0.6509 | 0.1150 | 0.2291 |
| 巴士 | **0.3952** | 0.6853 | **0.0032** | 0.2542 |
| 行人 | 0.2520 | 0.7736 | 0.0543 | 1.3926 |
| 骑行者 | 0.3919 | **0.5794** | 0.2282 | **0.1313** |

大型刚性车辆（巴士、卡车）检测最稳，行人最难——鱼眼图像中行人投影尺寸小、边缘畸变重。这与原始 Fisheye3DOD 的类别分布一致，是鱼眼感知的固有挑战，而非本方法特有的缺陷。

### 8.6 跨相机模型通用性（nuScenes 针孔 6 相机，初步）

同一套算子思路搬到 6 路针孔相机 nuScenes（扩展变体 v9/v10/v11），早期检查点达 0.1717~0.1903 NDS。远低于 nuScenes 先进水平，论文仅将其作为**"算子集可跨相机模型迁移"的证据**，不是精度声明。

## 第十章 局限性与未来方向（诚实清单）

论文对证据边界的交代非常坦诚，值得学习。

**已有证据支撑：**

- 核心路径只含 matmul / permute / softmax / 逐元素运算（代码可查证）；
- 推理不需要任何相机外参（`lidar2camera`、`ego2camera` 在前向路径中均不使用）；
- 规则内存访问 ⇒ NPU 高吞吐的架构论证成立；
- Fisheye3DOD 上 NDS 与基线差距仅 0.0052，朝向/尺度误差更优。

**明确标注为"进行中"：**

- J6 实板延迟、内存占用、INT8 量化精度（板端基准测试进行中）；
- 真实世界、多外参标定下的泛化能力；
- nuScenes 充分训练结果。

**本质权衡：**

1. **跨标定泛化是主要代价。** 空间映射全部学进权重后，矩阵会过拟合训练数据的相机安装几何与畸变特性。换一套外参，几何方法只需更新标定参数，本方法则需微调。工程解法：按车型在真实数据上微调投影矩阵（车产业界标准做法）、训练时做安装扰动增强、或叠加轻量标定自适应层。
2. **仿真到现实的差距（sim-to-real gap）。** 当前结果主要在 CARLA 仿真数据上；真实数据的光照、畸变、场景分布都不同，固定的学习矩阵无法像几何方法那样"换个标定参数就适应"。
3. **纯矩阵链可折叠。** v1~v3 的连续矩阵乘法间无非线性，理论上可合并为单个矩阵；v9~v11 插入批归一化正是针对此问题。
4. **mAP 仍低于几何基线**，小目标类别尤其明显，纯学习式映射可能损失部分细粒度定位能力。

README 附录还给出更多方向：跨视角权重共享（对称相机可减半参数）、用批量矩阵乘法（bmm）替代逐视角 Python 循环、用已知相机几何初始化矩阵加速收敛、用几何方法作教师网络做知识蒸馏、将 QAT 扩展到完整投影链验证 INT8 精度。

## 第十一章 总结

DeployMatBEV 给所有做车载感知的工程师上了一课：

> **相机到 BEV 的变换，应当从目标加速器的内存访问特性出发做架构设计，而不是先设计模型、再事后想办法转换。**

它用一组可学习的可分离矩阵，把 BEV 检测中最"硬件不友好"的视图变换环节，变成 NPU 最擅长的矩阵乘法；在 Fisheye3DOD 基准上以仅 0.0052 的 NDS 差距追平几何基线，总参数量减少 25.8%，推理完全摆脱对相机外参的依赖，并天然继承 INT8 量化的工具链红利。

对新手的三点启发：

- **部署友好性是架构级设计目标**，不是模型转换工具能自动解决的；
- "算子支持"与"算子高效"是两回事，本质区别在于**内存访问模式是否规则**；
- 放弃部分几何可解释性换取硬件效率，是量产落地中常见且合理的权衡——但代价（跨标定泛化）必须诚实面对。
